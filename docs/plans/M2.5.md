# M2.5 — The verified statutory rule spec

**Runs in parallel with M1, not after M2** (OPEN-DECISIONS Amendment 2). The CA
is an external dependency already on the critical path, this milestone ships no
product code so it contends with nothing, and M1 *already* commits to statutory
answers — `packages/money` has three open questions asserted in passing tests
right now.

ADR-0014 gates the money path on this. Nothing in `services/finance` that
produces a filed figure may land before the rules it depends on are `verified`.

## The problem in one line

`pnpm test` is green on statutory values that no chartered accountant has seen.

## Steps

**1. Extract — turn code into questions.** Done for the money boundaries:
`docs/statutory/QUESTIONS-FOR-CA.md` holds CA-01 to CA-06. The three `HUMAN(CA-nn)`
markers at `packages/money/src/rounding.ts:32,79,109` are CA-01 to CA-03. Extend the
document as new rules are ported; never let a question live only as a code
comment, because the CA will never read `rounding.ts`.

**2. Build the legacy oracle.** Record what the old system actually does, from
**synthetic inputs only**, into `packages/money/oracle/`. This is a *defect
report*, not an expectation — legacy output never becomes a golden value.

**UNRESOLVED CONFLICT — settle this before building the oracle.**
`_legacy/README.md:20` says of the legacy tree: "do not edit, **do not run, do
not import from it**", and `_legacy/README.md:1` says "Not a repository."
OPEN-DECISIONS Amendment 1 requires the opposite: the tree "pinned at a **named
commit** with **golden outputs recorded** from synthetic data" — which needs both
a repo and a run. Both cannot hold. Tracked as PO-12 in
`../../../HUMAN-INPUTS-NEEDED.md`; the alternative to a git pin is a sha256
manifest of the tree stored in this repo. **Do not build the oracle until this
is decided** — the rest of this step assumes the Amendment wins.

Technically feasible, verified: `_legacy/atelier-current/app/lib/estimationCalculations.js`
(33 lines) and `tdsChallan281.js` (57 lines) have **zero imports** and run
standalone. `paymentCalculations.js` (306 lines) imports only `queryAll,
queryGet` from `./db.js` — stub those two functions. No database and nothing
from `_private/` is required.

Run against the frozen tree (tag `legacy-frozen-2026-09-03` in the `_legacy`
repo) so the oracle cannot chase a moving target — OPEN-DECISIONS Amendment 1.
Where the legacy has two implementations of one rule that disagree, record
**both** and flag the divergence; the estimation formula already disagrees with
itself on 132 of 300 sampled inputs.

**3. Verify with the CA.** Walk `QUESTIONS-FOR-CA.md`. Each answer needs a
number or rule, its statute or circular, its effective date, and the CA's name.

**4. Encode as effective-dated rate tables.** TDS rates change every Budget, so
the engine is time-versioned: a voucher raised in FY2024-25 computes under
FY2024-25 rules forever. No rate exists without an `effective_from`.

**5. Lock with golden files per financial year.** `packages/money/golden/`,
format and promotion rules in its README. Only a human promotes `provisional` →
`verified`.

## Done when

- Every `HUMAN(CA-nn)` in `packages/money/src/` has a corresponding answered entry
  in `QUESTIONS-FOR-CA.md`.
- No golden file on the money path is still `provisional`.
- `/verify` reports **0 provisional cases** for `packages/money`.
- Every TDS rate carries a section, a payee class, a threshold and an
  `effective_from`, for every financial year with migratable vouchers.
- The oracle records both sides of every known legacy divergence.

## Not in scope

Fixing the legacy defects. ADR-0014 decision 5: **never fix a rule and port it
in the same commit.** The oracle records what the old system does; corrections
are separate commits behind tests, after the port is faithful.
