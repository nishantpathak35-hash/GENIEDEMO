# M5 — The internal app

**Status:** in progress — the API layer and the render worker are done; the view
port is the remaining bulk · **Date:** 2026-09-04

---

## The API layer — what unblocks all four apps

Everything through M4 was domain logic with no HTTP surface: `services/host`
mounted `/healthz`, `/readyz` and the connector routes, so no app could call
anything. That is now closed.

**The tenant middleware is the seam between HTTP and the database.** It resolves
a principal, builds the `TenantContext`, and wraps the handler in one
`withTenant` transaction. It is the only place a context is constructed.

Three decisions in it are load-bearing:

**One `withTenant` per request, not per route group.** The transaction is a unit
of work; holding one open across an external call pins a pooled server
connection and turns a slow dependency into pool exhaustion. The middleware is
where that rule either holds or quietly stops holding.

**A handler that returns 5xx rolls back.** Hono records a status rather than
throwing, so without an explicit check a failed handler would commit its partial
writes — which is how the legacy leaves a deleted PO's audit row behind when the
delete itself fails.

**`TENANT_NOT_RESOLVED`, never an empty list.** Under RLS a query with no tenant
set returns **zero rows** rather than erroring, so "the isolation layer refused"
is otherwise indistinguishable from "the table is empty". A 200 with `[]` would
be the worst possible answer. Verified live:

```
GET /api/v1/purchase-orders
403 {"code":"TENANT_NOT_RESOLVED","message":"No organisation could be
     determined for this request.","requestId":"df3a020e-…"}
```

### The route audit

A test that calls a handler with a hand-made context proves the **wrapper**
works and proves nothing about the **wiring** — and the wiring is what somebody
gets wrong next year by mounting a route one line above the middleware.

So `services/host/tests/route-audit.test.ts` enumerates what the router actually
registered and checks every entry against an explicit allowlist. Three
tenantless routes, each named with its reason:

| Route | Why |
|---|---|
| `/healthz` | Liveness must touch no dependency — a probe that checks Postgres restarts every container when Postgres blips |
| `/readyz` | Checks dependencies and the runtime role, reads no tenant data |
| `/connector/v1/*` | Resolves its tenant from a per-tenant bearer key rather than a user principal — a third case, named rather than exempted |

The audit is also asserted to **fail** on a route mounted at the root, because a
check nobody has seen fail is decoration.

## The render worker

ADR-0013's rule is that templates ship with the release and tenant input never
becomes template code — and **Typst is a programming language**, so a vendor
named `#read("/etc/passwd")` in an unescaped template is code execution inside
the renderer, and a `$` in a BOQ description silently opens a maths block.

Every value is escaped, template names are an allowlist so a name cannot become
a path, keys are pattern-checked because a key is emitted as an identifier, and
the archive record captures template version plus the **escaped** inputs — what
was actually rendered. The auditor's question is "show me the document you
issued", not "re-render it identically", which is what makes the snapshot the
evidence and renderer determinism secondary.

## `apps/web`

Scaffolded on **Turbopack with no Node-polyfill block**. That block existed only
because `jspdf` and `html2pdf.js` drag Node built-ins into the browser bundle,
which is why the legacy forces `--webpack` despite a `turbopack` block sitting
directly above it. Moving document rendering server-side is what unblocked it.
`ignoreBuildErrors` is absent, deliberately.

## Remaining, and it is the bulk

The ~20 view components are the M5 port, and M6 is three more apps. The rule
governing every one of them is already enforced server-side: 17 `'use client'`
files currently perform money arithmetic and derive roles in the browser, and
all of that computation now lives in `services/*/domain/` behind the API layer
above.

One vertical slice through that layer is done — `POST /api/v1/purchase-orders/price`
returns server-computed totals, so a screen displays what the server says
instead of computing its own answer and disagreeing with the database.
